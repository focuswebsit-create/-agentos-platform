# AgentOS | Commercial SaaS Blueprint v1.0
**מוצר:** פלטפורמת SaaS רב-ארגונית ורב-ענפית ליצירה, הפעלה ומעקב אחר סוכני AI וצוותי סוכנים.
**יעד:** חברות מכל ענפי הפעילות; השקה מסחרית ראשונה בישראל, עברית RTL ואנגלית LTR, ללא התאמות קוד ללקוח.
**סטטוס:** מסמכי תכנון בלבד — לא קוד פועל ולא חיבור סליקה אמיתי.
**עודכן:** 2026-11-09.

## מה השתנה לעומת Blueprint v0.1?
- שוק יעד: כל סוגי העסקים; כניסה דרך שימושים רוחביים ותבניות מוכנות, לא מוצר אנכי.
- MVP מסחרי כולל אתר שיווקי, הרשמה, onboarding, תבניות, חיוב מנוי, מכסות ו-Super Admin.
- Billing אינו עוד post-MVP: בנייתו נדרשת לפני גיוס לקוחות משלמים.
- לקוח יכול ליצור סוכנים ללא תקרת כמות מובנית, **אך** יש מכסות הרצות, צריכה, עומסים וכלים.
- בידוד לקוחות, מדידת עלות אמיתית ואישורי פעולות רגישות הם תנאי השקה.
- הגדרת 3 תוכניות מחירים *לניסוי ולאישור מסחרי*; אין אפשרות לחייב בפועל ללא תהליך סליקה מאושר ובדיקות.

## מפת קבצים
- `PRD.md` — מוצר, פרסונות, מסלולי שימוש ומדדי הצלחה.
- `ARCHITECTURE.md` — ארכיטקטורה, שרידות, בידוד וזרימות.
- `DATA_MODEL.md` — סכמת נתונים ומגבלות שלמות.
- `API_CONTRACT.md` — API ומצבי שגיאה.
- `SECURITY.md` — אבטחה, פרטיות ואישורי פעולה.
- `BILLING_AND_PLANS.md` — תוכניות, מנויים, entitlements, שימוש וגבייה.
- `MARKETING_WEBSITE.md` — תוכן וחוויית האתר הציבורי + onboarding.
- `SUPER_ADMIN.md` — מסכי ניהול-על והרשאות.
- `GO_TO_MARKET_90D.md` — תוכנית חדירה לשוק וניסויי מכירה.
- `UI_UX_SPEC.md` — מסכים ומצבי ממשק.
- `QUALITY_GATES.md` — בדיקות קבלה עסקיות וטכניות.
- `ROADMAP.md` — פיתוח בשלבים; לא לבצע הכול בפעימה אחת.
- `CLAUDE.md` — כללי עבודה ל-Claude Code.
- `prompts/` — פרומפטים מדורגים לביצוע.
- `SOURCES.md` — קישורים לנתוני ספקים ולתיעוד רשמי שנבדק בעת התכנון.

## התחלה ב-Claude Code
1. צור ריפו **נפרד** `agentos-platform`, וכן Supabase Development נפרד; לא לגעת ב-AutoMind.
2. פרוס את **תוכן** החבילה לשורש הריפו.
3. פתח את Claude Code בסביבת הריפו; בקש לקרוא `CLAUDE.md`, `PRD.md`, `ROADMAP.md`.
4. הפעל את `prompts/00_repo_audit_and_scaffold.md` בלבד; קבל PR + תוצאות CI.
5. המשך לשלב הבא רק לאחר עמידה בקריטריוני הקבלה. השתמש במצב sandbox לסליקה עד אישור חוקי/עסקי.

## עקרונות החלטה
- מוצר גנרי: תבניות הניתנות להרחבה, לא fork לכל ענף.
- מכירת מנויים ישירה לבעל עסק ולא white label ב-MVP.
- שליטה בצריכה לפני כל קריאה לספק מודל; חריגות דורשות הסכמה.
- אין להציג מדדי דמו, אינטגרציות או checkout מדומה כאילו היו נתוני אמת.
- פרטי רגולציה, גבייה, פרטיות וחוזים חייבים בדיקת בעל מקצוע מתאים לפני השקה.
