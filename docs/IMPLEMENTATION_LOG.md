## Defects found and fixed during P1

1. **Audit forgery.** `log_audit()` was `SECURITY DEFINER` with free `org_id`,
   `actor_type` and `action` parameters, granted to `authenticated`. Any
   signed-in user could have written an audit record in **any** organisation
   and impersonated `system` or `platform_admin`. Now internal only.
2. **Tenant-size oracle.** `org_seats_taken()` took an arbitrary organisation
   id and returned a headcount. Now internal, behind the membership-checked
   `org_seat_usage()`.
3. **Admin boundary could not read its own allowlist.** `BYPASSRLS` bypasses
   row security but **not** table privileges, and `service_role` was never
   granted `SELECT` on `platform_admins`. `/admin` would have failed closed for
   real administrators. Fixed with an explicit grant.
4. **Admin audit rows had no actor.** `log_audit()` derives the actor from
   `auth.uid()`; the platform-admin module connects with the secret key and has
   no JWT. Added `log_platform_audit()`, granted to `service_role` only.
5. **Missing CSRF on organisation creation.** `POST /api/orgs` changed state
   with no CSRF check, and the token cookie was only issued on `/app`, so
   onboarding had neither. All six API routes now verify origin and a
   double-submit token on every mutation.
6. **Server code in the client bundle.** The tenancy barrel re-exported
   `context.ts`, pulling `next/headers` into the browser and failing the
   production build. Server-only modules are separated and marked with
   `import "server-only"`.
7. **A security check that never ran.** The pre-commit scanner piped gitleaks
   into `tail`, so `$?` was always `tail`'s status and a real finding would
   have been swallowed. Separately, `ss` is not installed in this image, so the
   TCP-exposure check silently reported success. Both fixed; the TCP check now
   reads `/proc/net/tcp` and fails closed.

### Two defects found and fixed in this step

**1. The settings form would have reset real values.** It passed
`locale: "he"` and `timezone: "Asia/Jerusalem"` as the form's initial state
because `OrgContext` did not carry those columns. An organisation that had set
anything else would have been shown the defaults, and the first save would have
written them over the real values without anyone touching those fields. Fixed by
selecting both columns in `listMemberships` and threading them through.

**2. The RLS suite was testing a stale schema.** The first run after the change
reported 5 failures. None were regressions: `log_platform_audit()` and
`grant select on public.platform_admins to service_role` had been added to the
migrations after the local database was last built, and the suite does not
create the schema it tests.

The direction that matters is the opposite one. A policy *removed* from a
migration would still have passed, because the old policy was still live in the
cluster — a green gate asserting something the repository no longer says.
`scripts/db-reapply.sh` closes this: drop `public` and `auth`, recreate from the
shim plus every migration file, one transaction per file under `ON_ERROR_STOP`.
It refuses to run unless `PGHOST` is a unix socket path and `PGDATABASE` is the
disposable test database, so it cannot be aimed at a network host.

### What the 36 new checks cover

Cross-tenant negatives on both tables (0 rows, not an error); the role matrix
including `viewer` read-only and the member/admin split on archiving; the four
columns withheld from every customer role; published-version immutability from
the policy *and* from the trigger that also binds the schema owner; three
key-level rejections (second draft, cross-org version, cross-agent active
version); and two concurrent publishes of one agent producing versions 1 and 2.

### Four tests failed on first run — all four were test bugs

Recorded because a test that passes for the wrong reason is exactly what this
suite exists to catch, and three of these would have:

1. Three fixtures called `create_agent()` as the schema owner, which has no
   `auth.uid()`. The function correctly raised `AUTH_REQUIRED`; the assertions
   were "denied" either way and would have passed had they not named an
   expected message.
2. "A version cannot be filed under a different org" was being rejected by the
   one-draft-per-agent index, not by the composite foreign key it claimed to
   test. Fixed by inserting it as a published row so the partial index does not
   apply.
3. "A draft cannot be moved to another agent" was operating on a version that
   had been published earlier in the test, so the immutability guard answered
   before the identity guard. Fixed by targeting the live draft.

### Deliberate design choices, in full in ADR-0008

- `version` nullable, assigned at publish under a row lock.
- `agents.active_version_id` references `(agent_id, id)`, MATCH SIMPLE so drafts
  are legal, DEFERRABLE so the circular reference can be cascaded through.
- No DELETE trigger on `agent_versions`: it would make organisations
  undeletable. The DELETE privilege is simply not granted.
- No `AGENT_NOT_FOUND` code: unknown id and another org both answer
  `ORG_ACCESS_DENIED`.

### Two defects fixed during the work

1. `onClick={saveDraft}` handed React's `MouseEvent` to the function's first
   parameter, which had become `announce: boolean`. TypeScript refused it.
2. `publish()` awaited `saveDraft()` and continued regardless of the outcome. A

### Deliberate choices

- **Spend edited in dollars, stored as integer micros**, rounded to the nearest
  cent before scaling. `DATA_MODEL.md` forbids floating point for money.
- **Validation runs before `guardApi`** in every route, because the guard needs
  `submittedOrgId` from the parsed body to detect a workspace switched in
  another tab. A malformed body therefore answers 400 to an anonymous caller;
  the e2e test uses valid bodies so it exercises the guard and not Zod.
- **The demo studio was removed rather than left in place.** A disabled mock
  editor one URL away from a working one is a trap, not a placeholder.
- **No provider is configured, and the screen says so** before publishing, not
  after (CLAUDE.md rule 4). Publishing defines an agent; it cannot run one.

  accept "no organisation" would weaken every customer route.
- **JSON textarea, not a built form.** The configuration schema changes each
  phase and a bespoke form would fall behind it. The server validates and names
  the missing fields.

### `ACTIVATION_FAILED` is its own error

If the version is written but the pointer update fails, the response says so
instead of reporting a generic failure. An administrator told only "it failed"
would retry and create a duplicate version; one told the version exists can
roll back to it.

are exercised by the RLS suite only at the privilege level — that `service_role`
may write and customers may not. The publish flow itself has been typechecked
and built, not run.

### Decisions

- **Blocks runs only.** Reading, editing and export stay available. The
  specification says "suspend from new runs" and separately forbids silent
  deletion of account or content; locking a customer out of their own data
  would be closer to the second.
- **The check is under the budget's row lock**, so a suspension committed
  mid-dispatch cannot be stepped over.
- **A CHECK ties status, timestamp and reason together.** "Suspended with no
  reason" is unrepresentable, not merely discouraged.
- **The reason is readable by members**, and shown on every `/app` page. A
  workspace that stops working without saying why is an outage.
- **`service_role` only.** Not an owner action in any role: an organisation
  that can unsuspend itself is not suspended.
- **The audit row is written inside the RPC**, in the same transaction as the
  status change, so `adminSetOrgSuspended` deliberately does *not* call
  `auditOrRefuse` — that would double the record and open a window where the
  status changed and the log did not.
- **`ORG_SUSPENDED` is its own code.** `ORG_ACCESS_DENIED` is not actionable;
  this is.

against it. The behaviour is proven on the local cluster.

## 2026-11-14 — "the variables are set and it still says not configured"

### Root cause

Two bugs. The second was invisible without an experiment.

**1. The values never reached the browser.** `src/config/env.ts` read them as
`source.NEXT_PUBLIC_SUPABASE_URL`, with `source` a parameter defaulting to
`process.env`. That is a dynamic property access. `NEXT_PUBLIC_*` reaches a
browser only because Next.js replaces the literal text
`process.env.NEXT_PUBLIC_X` while the build runs — a browser has no
`process.env` — so the bundler saw no pattern and substituted nothing.

Measured: a build with both variables set produced **zero** client chunks
containing the URL value. After the fix, one each. Every browser-side auth call
was therefore throwing "not configured" whatever the host had.

`getSiteUrl()` had the identical defect, with no client caller yet.

**2. The notice is decided at build time.** Reproduced exactly: build with the
variables absent, run with them present, and `/sign-in`, `/sign-up` and
`/forgot-password` all still serve the notice while the server reports
configured at runtime. The auth layout's answer is in the prerendered shell.

Which means the baked answer was **correct** — a bundle built without the
variables cannot sign anyone in — and the real gap was that this is
indistinguishable from a missing variable from outside.

| `src/config/env.ts` | module-scope literal reads for both pairs; values trimmed; new `describeSupabasePublicEnv()` |

| `src/components/shared/config-report.tsx` | new — the browser half |
| `src/app/api/diagnostics/config/route.ts` | new — the server half as JSON |
| `docs/DEPLOYMENT.md` | a section on why `NEXT_PUBLIC_*` is build-time, and the four-case table |

### Three things that went wrong while fixing it

1. **`dynamic = "force-dynamic"` is rejected under `cacheComponents`.** The
   build failed with the config option named. Replaced with `connection()`.
2. **`instant = false` alone left the page static.** The build output said `○`,
   so the server half would have been baked — destroying the only thing the
   page is for. Both `instant = false` and `await connection()` are needed, and
   the comment in the file says so.
3. **The secret scanner flagged my own test fixtures** — a 20-character project
   ref before `.supabase.co`, and an `sb_publishable_` prefix. Allowlisting the
   file was the easy fix and would have left a hole in the file most likely to
   grow a real key. The fixtures are assembled at runtime instead: identical
   values, no credential-shaped literal in the source.

often carries a trailing newline; `z.url()` rejects
`"https://x.supabase.co\n"`, which read as absent and looked exactly like a
missing variable.
